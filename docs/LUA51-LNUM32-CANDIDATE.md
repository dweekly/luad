# Lua 5.1 LNUM32 candidate verification and real-firmware quickstart

Fresh as of: 2026-08-26.

Revalidate or delete when: the `lua5.1-lnum32` candidate is promoted to stable release,
candidate specification/schema changes, the qualification workflow changes, or the
real-firmware handoff workflow changes.

## Overview and candidate identity

The `lua51-lnum32-0.1.0-rc1` release candidate provides a reproducible, non-promoted binary package for investigating OpenWrt-derived Lua 5.1 bytecode.

### Candidate specification identity

- **Candidate ID**: `lua51-lnum32-0.1.0-rc1`
- **Target dialect**: `lua5.1`
- **Patch authority**: `Lua 5.1.5`
- **Profile**: `lua5.1-lnum32`
- **Layout**: `int=4,sizet=4,inst=4,num=8,endian=1,integral_flag=4`
- **Supported platforms**: `linux-x86_64` (`x86_64-unknown-linux-gnu`) and `macos-aarch64` (`aarch64-apple-darwin`)
- **Support status**: `experimental` (candidate artifacts are qualification evidence and do not promote capability status to supported)

### Blocking limitation

This candidate can report `open-register-window` for a statically resolvable callee
when a preceding open `VARARG` supplies arguments above the callee register. Treat such
an unresolved result as incomplete rather than evidence that the target is dynamic.
The candidate remains suitable for validation and bug reproduction, but it is not
eligible for promotion or a negative security conclusion until a rebuilt candidate
passes the open-window callee regression and customer replay.

## Obtaining and verifying CI candidate artifacts

Candidate artifacts are generated by explicitly dispatching the GitHub Actions
`Candidate Qualification` workflow on the revision being qualified. Its
`qualify-candidate-index` job attaches the complete bundle as a workflow run artifact.

### 1. Download candidate bundle

Download the `candidate-evidence-bundle` artifact from the CI run into a local directory:

```console
mkdir -p /tmp/luad-candidate-bundle
# Unzip downloaded candidate-evidence-bundle.zip into /tmp/luad-candidate-bundle
ls -la /tmp/luad-candidate-bundle
# Expected files:
#   candidate-index.json
#   attestation-linux-x86_64.json
#   attestation-macos-aarch64.json
#   luad-linux-x86_64.tar.gz
#   luad-macos-aarch64.tar.gz
```

### 2. Verify candidate index and platform attestation

Verify the multi-platform evidence index and the platform-specific archive sidecar:

```console
# Verify two-platform evidence index
cargo run -p luad-oracle --bin luad-candidate -- verify-index \
  --spec tests/candidates/lua51-lnum32-rc1.json \
  --artifact-root /tmp/luad-candidate-bundle \
  --index /tmp/luad-candidate-bundle/candidate-index.json

# Verify specific platform attestation (e.g. Linux x86_64)
cargo run -p luad-oracle --bin luad-candidate -- verify-platform \
  --spec tests/candidates/lua51-lnum32-rc1.json \
  --attestation /tmp/luad-candidate-bundle/attestation-linux-x86_64.json \
  --archive /tmp/luad-candidate-bundle/luad-linux-x86_64.tar.gz
```

### 3. Extract candidate archive

Extract the authenticated archive to an installation directory:

```console
mkdir -p /tmp/luad-install
tar -xzf /tmp/luad-candidate-bundle/luad-linux-x86_64.tar.gz -C /tmp/luad-install

# Check extracted archive contents
ls -la /tmp/luad-install/bin/luad
export LUAD_BIN="/tmp/luad-install/bin/luad"
"$LUAD_BIN" --version
```

## Checked redistributable fixture transcript

Before examining external firmware, verify the candidate binary against the repository's pinned redistributable authority fixture:

```console
cargo run -p luad-oracle --bin luad-candidate -- transcript \
  --spec tests/candidates/lua51-lnum32-rc1.json \
  --fixture tests/fixtures/authority/lua51-openwrt-lnum32/authority_lnum32.luac
```

This runs `inspect`, `validate`, `disasm`, `query`, `xrefs`, and `export` on the fixture, emitting a verified transcript JSON document that checks:
- selected binary SHA-256;
- input fixture SHA-256;
- exact LNUM32 profile and layout match;
- valid structured evidence from every analysis workflow.

## Real-firmware investigation quickstart

Firmware acquisition and unpacking are external, researcher-owned steps. `luad` operates strictly on authorized, already-unpacked firmware filesystems and compiled bytecode.

### 1. Inventory compiled Lua files

Scan the unpacked firmware tree to find candidate Lua bytecode chunks:

```console
find /path/to/unpacked_rootfs -type f \( -name "*.lua" -o -name "*.luac" \)
```

### 2. Inspect chunk interpretation and profile identity

Confirm that the target chunk matches the OpenWrt LNUM32 profile:

```console
"$LUAD_BIN" inspect /path/to/unpacked_rootfs/usr/lib/lua/luci/dispatcher.lua --format json
```

Expected output:
- `interpretation.base_dialect`: `"lua5.1"`
- `interpretation.profile`: `"lua5.1-lnum32"`
- `interpretation.validated_layout`: `"int=4,sizet=4,inst=4,num=8,endian=1,integral_flag=4"`

### 3. Query string constants and symbols

Search for specific string constants (e.g. system commands, IP addresses, paths) across the bytecode:

```console
"$LUAD_BIN" query /path/to/unpacked_rootfs/usr/lib/lua/luci/dispatcher.lua \
  --where 'constant.type == "string"' \
  --format json
```

### 4. Enumerate symbolic callees and unresolved reasons

Resolve symbolic module/function call targets and audit unresolved call sites:

```console
"$LUAD_BIN" callees /path/to/unpacked_rootfs/usr/lib/lua/luci/dispatcher.lua --format jsonl
```

### 5. Trace call argument origins

Trace value sources (constant literals, local registers, table lookups) for call arguments:

```console
"$LUAD_BIN" origins /path/to/unpacked_rootfs/usr/lib/lua/luci/dispatcher.lua --format jsonl
```

### 6. Traverse closure captures and cross-references

Inspect prototype references and closure upvalue bindings:

```console
"$LUAD_BIN" xrefs /path/to/unpacked_rootfs/usr/lib/lua/luci/dispatcher.lua --format json
```

### 7. Batch export firmware artifacts to streaming JSONL

Export comprehensive factual analysis records across all bytecode files in the unpacked firmware tree:

```console
"$LUAD_BIN" export /path/to/unpacked_rootfs/usr/lib/lua/**/*.lua \
  --format jsonl \
  --max-facts-per-file 50000 \
  --out /tmp/firmware_facts.jsonl
```

Non-bytecode or unreadable files are recorded as explicit skips in the streaming export output, and batch export returns exit code 0 when at least one input produces a valid file record.
